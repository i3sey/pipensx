# pipensx 1.7.1 validation

Checked on 2026-11-12. Release builds use `PIPENSX_VERSION=1.7.1`.

## Automated checks

- `PIPENSX_VERSION=1.7.1 make -f Makefile.pc -j2 all test`: passed,
  including the final live-network `test_manager`.
- `UBSAN_OPTIONS=halt_on_error=1 PIPENSX_VERSION=1.7.1 make -f Makefile.pc
  BUILD_DIR=build-pc/sanitize SANITIZE=1 -j2 test`: passed without ASan or UBSan
  reports after fixing unaligned accesses in the vendored 7z decoder.
- `PIPENSX_VERSION=1.7.1 make -f Makefile.pc
  BUILD_DIR=build-pc/fuzz-release fuzz-smoke`: passed, 1,000 runs per harness.
- `node tests/web_companion.cjs` with Playwright 1.65.0: passed. The fixture
  test covers six pages at five widths, both palettes, queue and library
  actions, file selection, settings, catalog transfer, and NRO replacement.
- Native/web translations, source-list checks, `git diff --check`, shell
  syntax, YAML parsing, and GitHub actionlint: passed.
- GitLab CI Lint: valid configuration, no errors or warnings.
- `make audit` with gitleaks 8.30.1: no leaks in the 604 commits checked before
  the preparation commits. The preparation commits are scanned separately.
- The release job's version guard accepted `1.7.1` and `v1.7.1`, rejected a
  mismatching tag and invalid version strings, and accepted an explicit manual
  build version. Its packaging commands ran locally; the archive contains only
  `switch/pipensx/pipensx.nro`, identical to the standalone NRO.

The HTTP regression failed before the connection fix and passed afterwards:
an idle keep-alive connection yields to a new request while the SSE connection
stays open. Existing connection-cap and pipelining tests also pass.

## Physical Switch

Built with `make switch` in the local `devkitpro/devkita64:latest` image,
mounted at `/work`, using two build jobs and LTO. The documented `:zstd` image
is absent on this workstation.

- Started 1.7.1 from the installed forwarder and loaded the catalog.
- Opened a game detail and its torrent file chooser without starting a game
  installation.
- Opened all six Web Companion pages against the real console. The rapid
  navigation/API sequence that had encountered `503 busy` passed after the
  HTTP fix. No JavaScript page errors occurred.
- Verified catalog upload responses: missing PIN returns 401, a checksum
  mismatch returns 400, and malformed catalog JSON returns 409.
- Reimported the console's own catalog: 23,819,782 bytes, 7,308 source entries,
  successful publication with a new catalog generation. Existing tasks stayed
  intact.
- Downloaded a controlled 2 MiB file through a torrent with a LAN web seed,
  read it back from SD, and matched SHA-256. Removed that test task and its
  data; the original six tasks remained.
- Staged and applied an NRO through the real companion API. The initial test
  exposed the older helper's forwarder return path: the loader relaunched the
  full app in the same process, causing a crash. With the corrected helper,
  application of the NRO returned to HOME without a crash. Repeated with the
  final binary, launched manually, and confirmed version 1.7.1, a new server
  instance, cleared staged state, and the original queue.
- Read back the final installed NRO and matched it to the release binary:
  `134b319a204b131a4ebbd157d5ea7df2febbc3f3c495f2fdbd637afc17de5abb`.

The corrected helper is supplied by 1.7.1. An older installed version still
extracts its older helper, so the first upgrade should use manual file copy;
see [release notes](1.7.1-notes.md).

## Coverage limits

This run did not install or remove a game package, exercise low-space NAND
installation, or run an overnight transfer/sleep-resume test. Package backend,
archive extraction, recovery, and queue behavior are covered by the native
suite; those tests do not establish physical-console behavior for every case.

Publishing is a separate step: pushing a release tag starts the GitLab release
pipeline. Preparing and pushing `main` does not publish a release.
