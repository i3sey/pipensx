# F-B. pipensx вместо eShop: applet-режим + фоновая загрузка — план реализации

Дата: 2026-07-26. Смежные документы: `SYSMODULE_PLAN.md` (фоновый демон),
`UI_PLAN.md` (F6 — кэш обложек), `PERF_PLAN.md`.
Все утверждения о коде подтверждены по исходникам; ссылки — `файл:строка`.
Утверждения о системе — по исходникам Atmosphère и заголовкам libnx.

Суть: плитка «Nintendo eShop» на HOME открывает pipensx. Для этого приложение
перестаёт требовать application mode и умещается в applet-лимит. Фоновая
загрузка при этом **не** является свойством апплета — она следует из выноса
движка в sysmodule.

---

## 0. Границы задачи

### 0.1 Три независимых куска

| Кусок | Где работа | Зависит от |
|---|---|---|
| A. Плитка eShop открывает наш код | конфиг Atmosphère + форк hbloader | ничего |
| B. Приложение живёт в applet-лимите | внутри pipensx | замер из §4 |
| C. Загрузка идёт, когда pipensx не на экране | sysmodule, вне апплета | `SYSMODULE_PLAN.md` |

A не требует ни строчки в pipensx. C не требует апплета. Только B — работа в
этом репозитории, и её объём определяется одним замером.

### 0.2 Ограничение, задающее архитектуру

Library applet живёт, пока qlaunch держит его на экране. По нажатию HOME
система просит апплет закрыться: `appletMainLoop()` возвращает false →
`brls::Application::mainLoop()` возвращает false (`main_switch.cpp:429`) →
цикл выходит → `webServer.shutdown()`, `updater.shutdown()`,
`manager.shutdown()` (`main_switch.cpp:455–457`). Процесс завершается.

Это не suspend, как у приложения, а завершение. Отсюда:

> **«Свернуть и качать» в applet-режиме невозможно by design.**
> Фоном может качать только процесс, жизненным циклом которого qlaunch не
> управляет, то есть sysmodule.

Прерванная установка не теряется: очередь персистится, куски проверяются при
возобновлении, уже закоммиченные пакеты пропускаются (README, «Interrupted
packages restart from their beginning»). Но пользователь увидит именно
прерывание, а не паузу.

### 0.3 Что даёт связка B + C

Как только движок и инсталлятор уезжают в демон, апплету остаётся UI и IPC —
и его бюджет падает примерно втрое. То есть B и C не конкурируют за время, а
удешевляют друг друга. Порядок в §6 это учитывает.

## 1. Целевая картина

```
HOME → плитка «Nintendo eShop» (010000000000100B)
         └─ atmosphere/contents/010000000000100B/exefs.nsp   (форк hbloader)
              └─ sdmc:/switch/pipensx/pipensx.nro            (тонкий фронтенд)
                   └─ IPC → сервис "pipensx"                 (sysmodule-демон)
                              ├─ очередь, torrent-движок, запись на SD
                              └─ psc sleep/wake
switch/.overlays/pipensx.ovl                                 (Tesla, статус поверх игры)
```

Апплет отвечает за каталог, выбор, постановку задач и просмотр статуса.
Демон — за загрузку и её продолжение. Оверлей — за управление во время игры.

## 2. Кусок A: запуск с плитки eShop

### 2.1 Цель

eShop — это **library applet**, не приложение:
`/opt/devkitpro/libnx/include/switch/services/applet.h:107` —
`AppletId_LibraryAppletShop = 0x14, ///< 010000000000100B "LibAppletShop"`.
Обычный системный тайтл в NAND, к нему применимы все механизмы подмены кода.

Прецедент: uMenu из uLaunch запускается именно так («running temporarily over
the *eShop applet*»).

### 2.2 Приоритет источников кода в loader

`libstratosphere/source/fs/fs_code.cpp`, `AtmosphereCodeFileSystem::DoOpenFile`:

| Приоритет | Источник | Как включается |
|---|---|---|
| 1 | external code | `ldr:shel` cmd 65000 в рантайме |
| 2 | HBL fs | `[hbl_config]` в `override_config.ini` |
| 3 | `/atmosphere/contents/<id>/exefs.nsp` | положить файл |
| 4 | `/atmosphere/contents/<id>/exefs/` пофайлово | — |
| 5 | настоящий NCA | — |

Важно для §2.4: если оставить запись в `override_config.ini`, она перехватит
раньше, чем `exefs.nsp`.

### 2.3 Шаг A1 — бесплатная проверка (0 строк кода)

`/atmosphere/config/override_config.ini`:

```ini
[hbl_config]
program_id_0=010000000000100D
override_key_0=!R
program_id_1=010000000000100B
override_key_1=!R
```

`!R` = по умолчанию перехват, с зажатым R — настоящий eShop. Плитка открывает
hbmenu. Этим закрываются два неизвестных:

1. пускает ли qlaunch в апплет без сети и аккаунта;
2. не ругается ли qlaunch на выход апплета без выходного хранилища.

Если ругается — лечится на стороне апплета: `appletPushOutData` перед выходом
(`applet.h:2155`, хранилище — `appletCreateStorage`, `applet.h:1358`).

### 2.4 Шаг A2 — форк hbloader

`switchbrew/nx-hbloader`, одна правка: `DEFAULT_NRO` (`source/main.c:6`) с
`sdmc:/hbmenu.nro` на `sdmc:/switch/pipensx/pipensx.nro`.

Почему форк, а не конфиг: `path=` в `[hbl_config]` — одна глобальная
переменная `g_hbl_sd_path` на все записи
(`cfg_override.board.nintendo_nx.inc`), Альбом и eShop пойдут в один и тот же
`hbl.nsp`. Отдельного «какой NRO грузить для этого program id» нет.

Собрать с NPDM по образцу `uLaunch/projects/uLoader/uLoader_applet.json`:

```
application_type : 2   (Applet)
pool_partition   : 0
handle_table_size: 512
debug_flags      : { allow_debug: false, force_debug_prod: false, force_debug: true }
service_access   : ["*"]
```

Debug-капабилити прописывать **явно**: `FixDebugCapabilityForHbl` в loader
применяется только на HBL-пути, а `exefs.nsp` — путь не-HBL.

Подпись не мешает: `ValidateMeta` (`ldr_process_creation.cpp:822`) проверяет
`mount.GetCodeVerificationData()`, то есть данные **базового NCA из NAND**,
который не трогали. SD-код подаётся отдельно и не проверяется.

Положить как `/atmosphere/contents/010000000000100B/exefs.nsp`, из
`override_config.ini` строку про `100B` убрать (§2.2).

### 2.5 Откат и риски

| Риск | Что делать |
|---|---|
| Нужно вернуть eShop | удалить папку `contents/010000000000100B` |
| Ссылки на магазин изнутри игр поедут в pipensx | побочный эффект, не лечится; знать заранее |
| HOS 22.x сломала завершение homebrew | на 21.x не проявляется; на 22.x Atmosphère везёт патчи к `am` |
| Обновление прошивки | подмена кода не привязана к build id и переживает; иконка (§7) привязана |
| Бан | uLaunch фиксирует случаи, но там подменяется qlaunch целиком; подмена `100B` заметна меньше, и консоль перестаёт ходить в eShop вообще |

## 3. Кусок B: влезть в applet-лимит

### 3.1 Что запрещает сейчас

```cpp
int main(int argc, char** argv) {
    // A library applet must only terminate after qlaunch asks it to close.
    if (!isApplicationMode()) {
        showApplicationModeRequired();
        return 0;
    }
```
`main_switch.cpp:174–181`; проверка — `ui_helpers.hpp:133–137`
(`appletGetAppletType()` против `AppletType_Application`), текст отказа —
`ui_helpers.hpp:139–153` («Album applet mode does not provide enough memory and
network sessions»).

Гейт написан по типу процесса, а решает **память**. Это и есть предмет правки.

### 3.2 Куда уходит память

| Статья | Лимит | Где |
|---|---|---|
| кэш декодированных обложек (RGBA, CPU) | **96 МиБ** | `game_metadata_service.cpp:41`, вытеснение — `cacheImageLocked:1088–1116` |
| текстуры nanovg (GPU/драйвер) | **не ограничен и не считается** | `async_image.hpp:44,63` — `nvgCreateImageRGBA` |
| индекс метаданных | 24 МиБ | `game_metadata_service.cpp:34` |
| каталог JSON | 16 МиБ | `catalog_service.cpp:25` |
| info-dict магнита | 8 МиБ | `catalog_service.cpp:27` |
| метаданные магнита | 8 МиБ | `magnet_resolver.cpp:40` |
| NRO самообновления | 64 МиБ | `update_service.cpp:41`, только при апдейте |
| потоковая установка | 68–96 МиБ | считается в рантайме, §3.3 |
| торрент-движок | ~8 МиБ | `SYSMODULE_PLAN.md` §2 |
| Borealis + nanovg + шрифты + GL | **не измерено** | — |

Две строки без числа — главный риск всей затеи, и §4 существует ради них.

Отдельно про декодер: воркеров два (`kImageWorkerCount`,
`game_metadata_service.cpp:43`), каждый держит транзиентный RGBA до 64 МиБ
(проверка `decodedBytes <= 64 * 1024 * 1024`, `game_metadata_service.cpp:1163`)
плюс копию под `downscaleRgba`. Пик декода не учтён ни в одном лимите.

### 3.3 Установщик — не проблема

`download_manager.cpp:319` вызывает `detectStreamRamBudget(pieceLengthBytes_)`
на старте задачи; при нехватке — честная остановка
(`download_manager.cpp:342`, `"Not enough free memory for stream installation."`).

Правило годности (`tests/test_stream_ram_budget.cpp:125–127`):

```cpp
const bool canFitMinimum = available >= budget.reserveBytes + 2 * pieceSize;
```

с `reserve = min(avail, min(256 МиБ, max(64 МиБ, avail/2)))`
(`stream_ram_budget.cpp:67–70`). Отсюда порог:

| piece length | нужно свободной кучи |
|---|---|
| 2 МиБ | 68 МиБ |
| 4 МиБ | 72 МиБ |
| 8 МиБ | 80 МиБ |
| 16 МиБ | 96 МиБ |

При 96 МиБ бюджет деградирует до peak 32 МиБ, lookahead 1 — медленно, но
работает. Измеряется реально: `queryHeapAvailableBytes` =
`mallinfo().fordblks + (fake_heap_end − sbrk(0))` (`stream_ram_budget.cpp:40–58`),
плюс `svcGetInfo(InfoType_TotalMemorySize / InfoType_UsedMemorySize)`
(`stream_ram_budget.cpp:169–176`). Обе метрики работают в applet-режиме без
правок.

Единственная ловушка: если детект кучи не сработал, берётся
`kFallbackAvailableBytes = 384 МиБ` (`stream_ram_budget.cpp:20,151–152`) — в
applet-режиме это оптимистичная выдумка. Мера M0 ниже.

### 3.4 Меры, по возрастанию стоимости

**M0. Не врать при отказе детекта.** Fallback 384 МиБ оставить только для
application mode; в applet-режиме при `!heapDetected` считать бюджет
непригодным. Правка в `selectStreamRamBudget` (`stream_ram_budget.cpp:148`),
покрывается существующим тестом.

**M1. Гейт по памяти вместо гейта по типу процесса.** Общий `MemoryProfile`
(те же два `svcGetInfo`, что в `stream_ram_budget.cpp:169–176`), вызывается из
`main()` и из бюджета. `isApplicationMode()` остаётся диагностикой, но не
запретом. Текст `showApplicationModeRequired()` (`ui_helpers.hpp:139`) не
удалять, а переписать под «мало памяти»: он писался не на пустом месте.

**M2. `kMaxImageCacheBytes` из константы в функцию от кучи.** Сейчас 96 МиБ с
комментарием «96 MB sits mid-range of the 64-128 MB plan window», то есть это
выбор, а не физика. Предлагается `min(96 МиБ, avail / 8)`. Механизм вытеснения
менять не нужно: LRU-развёртка в `cacheImageLocked:1101–1110` уже есть,
меняется только потолок.

**M3. Считать текстуры nanovg.** Сейчас `nvgCreateImageRGBA` вызывается на
каждый показ обложки и на каждое открытие полноэкранного просмотра
(`async_image.hpp:44,63`), а бюджета у этой памяти нет вообще. Нужен счётчик и
потолок; при переполнении — не создавать текстуру, показать плейсхолдер.
Сначала измерить (§4), потом решать, обязательна ли мера.

**M4. `kImageDimFull` по режиму.** 1280×1280×4 ≈ 6.5 МиБ на одну картинку
(`game_metadata_service.hpp:83`). В applet-режиме понизить до 720.

**M5. Индекс и каталог.** 24 + 16 МиБ (`game_metadata_service.cpp:34`,
`catalog_service.cpp:25`) — понижать в последнюю очередь: это ломает данные, а
не украшательство.

**M6. Отключаемое.** WebServer (`main_switch.cpp:328–342`), DHT-кэш, проверка
обновлений на старте — в applet-режиме по умолчанию выключить, вернуть
настройкой.

**M7. Не код: `applet_heap_reservation_size`.** hbloader по умолчанию
удерживает `0x8600000` = 134 МиБ под другие апплеты
(`nx-hbloader/source/main.c:132–148`, шаблон
`Atmosphere/config_templates/system_settings.ini:74–82`). Обнуление в
`system_settings.ini` возвращает их приложению — ценой риска для остальных
апплетов. Пробовать только после §4, и знать, что это глобальная настройка.

Порядок применения — по результатам замера. Делать все семь сразу не нужно.

## 4. Замер — гейт перед всей работой куска B

**Z0. Грубая цифра, 30 минут, кода ноль.** Запустить hbmenu через Альбом,
прочитать показанный объём памяти в applet mode. Меньше ~200 МиБ — идти сразу
к куску C и делать апплет тонким.

**Z1. Точная цифра.** Временная сборка: закоротить гейт `main_switch.cpp:178`,
запустить через A1 (hbmenu над плиткой eShop), снять из
`sdmc:/switch/pipensx/pipensx.log`:

- `[startup] applet_type=… operation_mode=…` (`main_switch.cpp:224`) —
  подтверждение режима;
- `[install] RAM budget source=… available=… reserve=… peak=… lookahead=…` —
  то, что видит установщик.

Снимать в четырёх точках: сразу после старта; после загрузки каталога и
индекса; после прокрутки ~100 обложек; во время установки.

**Критерий.** После прокрутки каталога остаётся ≥ 100 МиБ свободной кучи —
установка влезет, дальше только меры M0–M2. Остаётся 60–100 МиБ — нужны M3–M6.
Меньше 60 МиБ — кусок B в текущей архитектуре не решается, апплет обязан стать
тонким (кусок C).

## 5. Кусок C: фоновая загрузка

### 5.1 Три разных «фона»

| Уровень | Что значит | Чем достигается | Состояние |
|---|---|---|---|
| Ф1 | качает, пока pipensx открыт | уже работает | есть |
| Ф2 | качает, пока идёт игра или закрыт апплет | sysmodule-демон | `SYSMODULE_PLAN.md`, не начат |
| Ф3 | качает, пока консоль спит | half-awake через `bgtc` | не доказано, нужен зонд |

### 5.2 Что берётся из `SYSMODULE_PLAN.md` без изменений

Разделение ответственности (§1.1), IPC-протокол сервиса `pipensx` (§3, 11
команд, поллинг вместо push), набор сервисов (§1.2), бюджет ~8 МиБ прототипа
и ~2–3 МиБ после оптимизации (§2).

### 5.3 Что меняется из-за апплета

Апплет становится IPC-клиентом, и из его бюджета уходят: торрент-движок
(~8 МиБ), piece-буферы, пик потоковой установки (68–96 МиБ), сокет-буферы
движка. Остаются UI, каталог, индекс и кэш обложек. Иначе говоря, **кусок C
решает кусок B**, а не добавляется к нему.

Обратная сторона: установка через `ncm`/`es`/`ns` в демоне не предусмотрена
(`SYSMODULE_PLAN.md` §1.1 явно оставляет stream-install приложению). Пока это
так, «скачать фоном → поставить при следующем открытии плитки» — рабочая
модель, а «поставить фоном» — нет.

### 5.4 Поправка к §0.3 `SYSMODULE_PLAN.md`

Там сказано, что фоновые загрузки Nintendo используют «системный
low-power-режим, недоступный homebrew». Первая часть («в SC7 всё
приостановлено») верна, вторая — нет: режим называется half-awake и управляется
обычным сервисом `bgtc` (`bgtc:t` cmd 4 `IsInHalfAwake`, 103
`WillStayHalfAwakeInsteadSleep`, 200 `EnableStayHalfAwake`), а держать сеть
поперёк засыпания умеет `nifmRequestSetKeptInSleep` — обёртка уже есть в libnx
(`nifm.h`).

Вывод «нельзя» при этом **не опровергнут**, а лишён обоснования: не проверено,
получают ли потоки homebrew процессорное время внутри окна half-awake. Зонд из
трёх стадий (NRO → минимальный sysmodule → сеть во сне) описан в исследовании
и стоит вечера на первую стадию. До его прохождения Ф3 остаётся не-целью.

## 7. Иконка (Ф6, отдельно от всего)

Подмена кода не трогает плитку: на HOME остаётся значок eShop. Меняется темой
NXThemes типа `home`; целевая текстура — `RdtIcoShop^s` в
`ResidentMenu.szs`, пейн `P_Pict`, **ровно 64×56**
(`SwitchThemeInjector/SwitchThemesCommon/Layouts/PatchTemplate.cs:370`).

Два ограничения:

- JPG запрещён (`NxThemeTool/NxTheme.cs`, `Validate`: «JPG images are not
  allowed for icons.»), размер проверяется точно, без ресайза. То есть
  `resources/icon.jpg` (256×256) и `resources/icon.png` не годятся напрямую —
  глиф надо рисовать заново под 64×56.
- ChannelTypes `0x5050505` = все четыре канала берутся из **Alpha**. Текстура
  работает как маска: цвет отбрасывается. Стрелка со скобой из текущей иконки
  переносится хорошо, кольцо и подложка — нет.

Цена обслуживания: инсталлятору нужен exefs-патч qlaunch, привязанный к его
build id, поэтому **тему снимают до обновления прошивки** (иначе консоль может
не загрузиться; лечится удалением `/atmosphere/contents/0100000000001000`).
С кусками A и B не конфликтует — разные тайтлы.

## 8. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Borealis/GL съедает столько, что каталог не помещается | средняя | Ф0 измеряет до всякой работы; ответ — Ф4 |
| Текстуры nanovg растут без потолка | средняя | M3, после замера |
| qlaunch требует выходное хранилище от shop-апплета | низкая | `appletPushOutData` в шиме hbloader |
| Пользователь нажал HOME посреди установки | высокая | не баг: очередь и проверка кусков восстанавливают; предупредить в UI |
| `applet_heap_reservation_size = 0` ломает другие апплеты | средняя | настройка глобальная; менять последней и уметь вернуть |
| Обновление до HOS 22.x ломает завершение homebrew | средняя | не обновляться до проверки; на 22.x нужны патчи `am` из комплекта Atmosphère |
| Самообновление недоступно под своим hbloader | низкая | `envHasNextLoad()` уже проверяется (`main_switch.cpp:369`); при отсутствии — сообщение вместо тишины |

---

## 9. Критерии приёмки

1. Плитка eShop открывает pipensx; удержание R открывает настоящий eShop.
2. Приложение стартует в applet-режиме без специальных настроек прошивки,
   доходит до каталога и рисует обложки.
3. Строка `[install] RAM budget …` в логе показывает `valid` на торренте с
   piece length 4 МиБ, и установка доходит до конца.
4. Нажатие HOME завершает апплет чисто: очередь сохранена, следующее открытие
   продолжает с того же места.
5. Удаление `/atmosphere/contents/010000000000100B` возвращает eShop.
6. После Ф4: закрытый апплет не останавливает загрузку.

## 10. Явные не-цели

- Загрузка во сне (Ф3) — до результатов зонда §5.4.
- Установка (`ncm`/`es`/`ns`) из демона.
- Подмена подписи «Nintendo eShop» под значком: она берётся из
  message-архивов qlaunch, а не из темы.
- Замена qlaunch целиком (путь uLaunch) — избыточно и заметнее для системы.
- Application-режим не выпиливается: он остаётся штатным способом запуска и
  даёт больше памяти.
