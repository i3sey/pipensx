## Запуск и forwarder

В исходниках [mGBA 0.10.5](https://github.com/mgba-emu/mgba/blob/0.10.5/src/platform/switch/main.c)
при `argc > 1` вызывается `mGUIRun(&runner, argv[1])`.
В [pGBA 7.2](https://github.com/Cpasjuste/pemu/blob/v7.2/src/cores/main.cpp)
проверяется существование `argv[1]`, затем выделяются папка ROM и имя файла.
Это подтверждает предполагаемый контракт аргументов на уровне исходников.
Запуск mGBA в режиме приложения без внешнего BIOS дополнительно проверен
на компактной Pong ROM (см. результаты ниже). Требования других игр
и фактический запуск pGBA остаются непроверенными.

В репозитории уже есть `vendor/autorun-forwarder/builder.h`:
`pipensxBuildForwarder` принимает application ID, NRO и строку аргументов,
создаёт NSP с loader NSO/NPDM и RomFS `nextNroPath`/`nextArgv`.
Происхождение и лицензии описаны в
[README генератора](../../vendor/autorun-forwarder/README.md).
`generateAutorunStubNsp` в `src/app/autorun_service.cpp` использует этот
генератор, но жёстко задаёт Wine NRO. Для ретро нужен общий вызов генератора,
а не Wine-конфигурация. Установку можно вести через `InstallBackend`.

До реализации ретро-forwarder остаются открытыми:

- Проверка loader с обоими эмуляторами, пробелами и кириллицей в пути ROM.
- Выбор диапазона application ID и проверка конфликтов с установленными
  приложениями. ID должен зависеть от стабильной записи библиотеки,
  сохраняться при смене эмулятора и не вычисляться только из названия.
- Проверка повторной установки, удаления и возвращения из эмулятора.

## Архивы ROM

`src/app/port_archive.cpp` реализует ZIP и 7z через zlib и vendored LZMA SDK.
Сопоставление файлов предназначено для NRO/LayeredFS; переносить его на ROM
нельзя. Хостовый `7z` успешно распаковал исследованный пакет mGBA, но это
не проверка распаковщика приложения на консоли.

`src/app/remote_archive.cpp` читает метаданные ZIP/RAR4 для удалённых
групповых загрузок. Полной распаковки RAR/RAR5 этот код не предоставляет.
Поддержка RAR5, защищённых и многотомных архивов остаётся открытой.
Новый ROM-распаковщик должен иметь собственные ограничения ресурсов,
проверки путей и владение файлами из основного плана.

## Начатая реализация данных

`src/app/retro_catalog.hpp` и `.cpp` вводят отдельную `RetroRelease`:
платформа, исходная тема, hash, серийный номер, ROM-set, описание и изображения.
Ключ записи состоит из платформы и темы. Разные темы с одинаковым hash
не объединяются. Серийный номер не становится Switch application ID.

Парсер GBA публикует только целиком валидный снимок. Ошибка оставляет
предыдущие записи у вызывающего кода. Относительные пути изображений
разрешаются через отдельный корень изображений. Источники задаются явным
списком с предпочтительным зеркалом; Switch-дельта не используется.

Это основа слоя данных. Фоновая загрузка, дисковый кэш, разбор статистики
и манифеста эмуляторов, UI и операции подготовки ещё не подключены.
`tests/test_retro_catalog.cpp` проверяет контракт данных и принимает путь
к реальному `gba_games.json` для проверки совместимости без фиксации дампа
в репозитории.

## Сервис каталога и кеш (2026-11-16)

`RetroCatalog` загружает `gba_games.json`, `console_games_stats.json` и
`emulators.json` с одного источника. Ошибка HTTP или валидации любого файла
переключает весь снимок на следующий источник. Смешивание файлов разных
зеркал не производится; сервер не предоставляет общего номера ревизии,
поэтому одновременность публикации трёх файлов не гарантируется.

`refreshAsync` возвращает future с результатом обновления и последним
доступным кешем. Токен отмены принадлежит вызывающей стороне; фоновая задача
сохраняет копию сервиса, поэтому уничтожение исходного объекта не оставляет
висячего указателя. Вызывающая сторона должна хранить future до завершения:
уничтожение future от `std::async` может ожидать задачу. Подключение этого
сервиса к жизненному циклу приложения и экрану «Ретро» ещё не выполнено.

Кеш находится в `<appRoot>/retro/`: основной `catalog.json` и последний
валидный `previous.json`. Сохраняются исходные JSON и идентификатор разрешённого
источника. Загрузка повторно проверяет все данные и восстанавливает базу
изображений. Размер каждого ответа ограничен 8 MiB, файла кеша 24 MiB + 4 KiB.
Запись идёт через временный файл с flush/fsync; до замены основного файла
сохраняется предыдущая валидная версия. Учтён отказ rename поверх существующего
файла на SD. Это восстановление из двух версий, не гарантия против повреждения
всей файловой системы или аппаратного отказа SD.

Статистика хранится по topic ID, GBA-пакеты выделяются из списка поддерживаемых
платформ. Удалённые `install_path` и `extract_dir` не входят в модель пакета:
будущую установку определит локальный адаптер. Наличие пакета в модели не
означает подтверждённую совместимость или готовность профиля к выпуску.

Нативные проверки покрывают повреждённый файл источника, переключение зеркала,
перезапуск с кешем, отсутствие сети, повреждение основного кеша, сохранение
предыдущей версии после неудачного обновления, отмену и превышение лимита ответа.
На локальном текущем наборе разобраны 26 раздач, 8 898 записей статистики и
два GBA-пакета. Новое физическое тестирование Switch не проводилось.

Проверки этого этапа: полный `make -f Makefile.pc test` завершился с кодом 0,
включая `test_manager`; после добавления сценария превышения лимита повторно

## Локальный профиль и установщик mGBA (2026-11-16)

Добавлены `src/app/retro_emulator.hpp/.cpp`. Профиль `mgba` описывает GBA,
расширение `.gba`, стандартный путь `sdmc:/switch/mGBA/mGBA.nro` и требование
режима приложения. `detect` проверяет обычный файл по этому пути и заголовок
NRO0 с размером исполняемой части. Это кандидат для профиля: наличие заголовка
не подтверждает подлинность вручную заменённого файла или версию эмулятора.
Ручной выбор другого NRO и интеграция запуска с жизненным циклом приложения
остаётся следующим этапом.

`install` принимает только исследованный mGBA 0.10.5: точные URL, имя пакета,
размер и признак архива должны совпасть с локальным адаптером. После загрузки
проверяются размер и закреплённый выше SHA-256 исследованного пакета. Это
локально зафиксированный отпечаток, не контрольная сумма из манифеста или
опубликованная подпись автора. Другие версии и pGBA не устанавливаются этим
адаптером. Настройки и пути из удалённого манифеста не управляют распаковкой.

7z распаковывается существующим декодером в изолированную временную папку,
с явным относительным сопоставлением. Проверяются размер распаковки и solid
блока (до 16 MiB), количество файлов (до 64), наличие ожидаемого NRO и его
заголовок. В конечную папку переносится только NRO: документы и лицензии из
архива не публикуются рядом с пользовательскими файлами. До загрузки проверяется
свободное место для пакета, распакованных данных и запаса 1 MiB.

Существующий NRO, включая повреждённый файл или символьную ссылку, вызывает
конфликт. Обновление и замена не выполняются. Файлы `config.ini`, ROM,
сохранения и прочее содержимое `/switch/mGBA` не включаются в операцию.
Незавершённая `.pipensx-install` очищается при следующей установке, только
если содержит точный маркер принадлежности установщику; пустая папка также
может быть переиспользована. Чужая непустая папка или ссылка вызывает ошибку.
После отмены или штатной ошибки собственная временная папка удаляется.
Проверенный NRO синхронизируется перед публикацией. На Switch публикация
состоит из одного rename на той же SD; на POSIX-хосте используется link,
чтобы не заменять появившийся файл. Отдельного
журнала многофайловой установки нет. Повторная установка после завершения
возвращает конфликт, после прерывания до публикации заново скачивает пакет.

`launchArguments` формирует два аргумента в кавычках, проверяя безопасные пути
`sdmc:/` и расширение ROM, включая имена с пробелами и UTF-8. Метод не вызывает
libnx, не проверяет наличие ROM и не запускает приложение. Требование режима
приложения должен применить будущий код запуска. Нативная проверка строки
аргументов не заменяет тест запуска такого пути на Switch.

Проверки установщика включают повреждённый/укороченный/слишком большой пакет,
неподдерживаемые URL и версию, отмену до и во время загрузки, существующий NRO,
символьную ссылку, отказ удаления чужой временной папки и восстановление своей.
Дополнительный запуск `test_retro_emulator /tmp/pipensx-retro-audit/mGBA-switch.7z`
выполнил установку ранее скачанного реального архива во временный каталог
хоста: получен NRO размером 7 268 339 байт, настройки и сохранение сохранились.
Отдельно проверен конфликт с файлом, появившимся во время загрузки.

Физический Switch по указанию пользователя недоступен для этого этапа и не
использовался. Установка из интерфейса pipensx, фактический запуск через новый
профиль и HOME-forwarder пока не проверены и не подключены к интерфейсу.

Финальная валидация этапа: чистый полный `make -f Makefile.pc test` через Bear
завершился с кодом 0, включая `test_retro_emulator` и сетевой `test_manager`.

с консолью не выполнялось. Список исходников, локальные ссылки документации
и проверки пробелов прошли. Интерфейс и продуктовые тексты не изменялись.

## Загрузка и подготовка ROM (2026-11-16)

Добавлены `RetroRomStore` и экран параметров загрузки. Из карточки раздачи
открывается выбор папки ROM, установленного mGBA либо скачивания без эмулятора,
затем существующий пикер файлов. Папка задаётся путём относительно корня SD;
это текстовое поле с проверкой пути, не файловый браузер. На экране заранее
показывается конечная папка `sdmc:/<выбор>/gba-<topic_id>` и политика хранения.
При выборе mGBA NRO проверяется перед получением файлов; установку можно открыть
отдельным действием. Без эмулятора загрузка и подготовка также доступны.

Используется сохранённый выбор источника приложения. При разрешённом BitTorrent
работает существующий `MagnetResolver`; иначе применяется фабрика выбранного
debrid-провайдера и `createDebridWithMetainfoFallback`. При отказе debrid прямой
торрент автоматически не включается. Подключены TorBox, TorrServer, Real-Debrid
и AllDebrid через их существующие адаптеры; работа с реальными аккаунтами этим
этапом не проверялась. В тестах менеджер запускается без рабочих потоков,
так что проверка маршрутизации не является загрузкой с этих сервисов.

### Очередь и записи операции

Для ретро пикер работает в отдельном режиме: только `Download` и `Skip`,
без пресетов и переходов к установке NSP, NRO или портов. Подтверждение сохраняет
план, затем импортирует задачу `DownloadOnly`. Очередь скачивает в собственную
папку загрузок; выбранный ROM-каталог заполняется отдельной подготовкой после
полного завершения. Это копирование, не прямой вывод сетевого потока в выбранную
папку. Такой порядок использует существующие механизмы возобновления всех
источников и сохраняет скачанное при отказе распаковки.

`importTorrentActions` и `importDebrid` получили необязательный `requireNewTask`.
Ретро включает его: проверка существующего hash под mutex менеджера отказывает
до объединения выбора файлов или изменения режима. Обычные вызовы сохраняют
прежнее объединение. Это защищает в том числе существующую установку Switch-игры
от повторного импорта того же hash как ретро. Сериализация очереди не менялась:
исходники по-прежнему записывают версию 9, новых полей DownloadTask нет.

Планы лежат отдельно: `<appRoot>/retro/operations/gba-<topic>.json`, формат 1.
Они содержат topic ID, hash задачи, название исходной раздачи, папку назначения,
привязку `mgba` либо пустую, признак готовности и найденные игры с выбором.
API-ключей и URL аккаунтов в этих записях нет. Запись идёт через временный файл,
flush/fsync и предыдущую валидную версию. Неудачный импорт может оставить план
без задачи; его можно повторно использовать с теми же параметрами. Другой путь,
hash или эмулятор вызывает конфликт, а не незаметное перемещение данных.

### Подготовка

«Загрузки ROM» доступны из каталога и с экрана параметров. После завершения
задачи пользователь открывает её операцию и выбирает подготовку. Рабочий поток
берёт `ExternalDeployLease`, останавливающий сидирование и защищающий исходные
файлы от удаления или очистки очереди. Отбираются только выбранные присутствующие
файлы из полного манифеста; проверяются тип обычного файла, отсутствие ссылок
в пути и точный размер. Установка пакетов через этот путь не вызывается.

Для распаковки подключён libarchive (PC: `libarchive-dev`, Switch:
`switch-libarchive`). Дополнены инструкции сборки, CI и проверка portlibs.
ZIP, 7z, RAR4 и RAR5 читаются в отдельную временную папку без правил раскладки
портов. Исходники сохраняются под `files/`, содержимое каждого архива под
`unpacked/<SHA-256 пути архива>/`. Вложенные архивы обрабатываются последовательно,
без удержания всех распакованных данных в RAM. Ссылки, специальные файлы,
небезопасные UTF-8/FAT-пути, коллизии имён, зашифрованные и многотомные варианты
отклоняются. Проверяется количество реально записанных байт, ошибка декодера
или CRC не разрешает публикацию результата.

Для RAR4/RAR5 добавлена отдельная проверка ограниченных заголовков, их CRC,
размеров и смещений, признаков томов/шифрования и файловой CRC, если она есть.
Причина: libarchive 3.7.2 пропускает проверку файловой CRC некоторых stored-RAR5
записей. Регрессионный тест с изменённым байтом ROM в таком контейнере теперь
отказывает до публикации. Для RAR4 и RAR5 с CRC=0 наличие контрольной суммы
также учитывается, а ноль не трактуется как отсутствие проверки. Встроенные
проверки ZIP/7z не отключаются. SFX/встроенные RAR, неизвестный размер и
неподдерживаемые декодером варианты не заявляются как рабочие.

Текущие ограничения показаны до начала загрузки: 2 GiB выбранных исходников,
512 MiB суммарных распакованных данных, 8192 записей, три уровня архивов.
До копирования и при записи файлов проверяется свободное место с запасом 8 MiB.
Это ограничивает запись на SD, а не задаёт независимый жёсткий лимит памяти
внутри стороннего декодера. Крупные ROM-сеты могут не помещаться в эти границы;
полная поддержка всех сборников каталога не считается достигнутой.

Ищутся `.gba` размером от 192 байт до 32 MiB. Проверяются фиксированный байт
заголовка и его контрольная сумма. Это отбор кандидатов GBA, не проверка
совместимости игры. Название берётся из заголовка либо имени файла, а не
копируется с карточки сборника. ID складывается из ID операции и SHA-256
пути ROM; повтор подготовки не создаёт новых записей. Единственная ROM
выбрана по умолчанию, для сборника выбор сохраняется через список найденных игр.

### Публикация и восстановление

Данные готовятся в `.pipensx-gba-<topic>.pending` в выбранной папке. Очистка
разрешена только с точным `owner.json` для этой операции; чужая папка вызывает
ошибку. При отмене собственная временная папка удаляется, исходная загрузка
сохраняется. Проверенный результат с `receipt.json` публикуется одним rename
в новую папку `gba-<topic>` на той же SD. Существующая чужая папка не заменяется.
Сохранения или настройки в ранее опубликованной папке не включаются в повторное
копирование и не удаляются.

Если запись операции прервётся после публикации папки, повторная подготовка
восстанавливает её из receipt, в том числе без исходной задачи очереди.
Перед восстановлением проверяются принадлежность и заголовки ROM. Выбор игр
пишется в receipt и запись операции. Подготовка сериализуется отдельно от
коротких операций чтения/записи планов, чтобы добавление загрузки не ждало
длительной распаковки под общим mutex. Ошибка подготовки остаётся видимой до
следующего действия пользователя. Записи пока не добавляются в «Мои игры»;
запуск, выбор другого NRO, удаление и forwarder относятся к следующим этапам.

### Известное ограничение RAR4

На хостовом libarchive 3.7.2 выявлен отказ на валидном upstream-образце
`test_read_format_rar_multi_lzss_blocks.rar`: независимый UnRAR 7.00 даёт
`All OK`, но libarchive выдаёт другие данные и ошибку файловой CRC. Проверка
выполнена через оба потоковых API libarchive, без изменения ожидаемой CRC.
Это ограничение декодера, не подтверждение повреждения исходного архива.
В приложении такой результат не публикуется, скачанное остаётся доступным.
Исправление или обновление этого декодера требуется до заявления полной
совместимости RAR4. На физическом Switch вариант не проверялся.

Воспроизведение после сборки теста:

```sh
build-pc/tests/test_retro_rom /tmp/pipensx-retro-audit/pong-Pong-Homebrew-GBA.gba \
  tests/fixtures/retro/rar4-large-lzss.rar
```

Исследованный прогон завершился кодом 2 с `File CRC error`. Это отдельный
неуспешный compatibility probe, он не записан как PASS обычного тестового набора.
Происхождение небольших reference-архивов и лицензия находятся в
[tests/fixtures/retro/README.md](../../tests/fixtures/retro/README.md).

## Библиотека и запуск из pipensx (2026-11-16)

Выбранные подготовленные игры добавляются в отдельную библиотеку
`retro/library/gba-<topic>.json`. Снимок хранит исходный hash/topic, папку,
профиль эмулятора и отдельные стабильные ID, имена и пути ROM. Повторное
добавление объединяет выбранные игры по ID; изменение выбора в операции
само по себе не удаляет уже добавленные игры. Добавление сверяет запись
подготовки с receipt и проверяет выбранные ROM. Неизвестная или повреждённая
запись библиотеки не перезаписывается при добавлении.

Файлы библиотеки используют существующую ограниченную атомарную запись с
`.previous` и восстановлением последнего читаемого снимка. Это восстановление
может вернуть предыдущий состав библиотеки при повреждении текущего снимка.
После удаления последней игры сохраняется пустая запись. Удаление записи
не удаляет ROM, исходники, архивы, saves, конфигурацию или эмулятор.
Библиотека не требует наличия исходной задачи или operation JSON после
добавления, но запуск требует сохранённого receipt и правильного ROM.

Доступ к библиотеке добавлен во вкладку «Ретро» и в панель «Мои игры».
Это пока отдельный список, а не все четыре подраздела «Моих игр» из плана.
Детали игры показывают путь и действие «Запустить в mGBA» независимо от
исходного выбора «без эмулятора»: пользователь явно выбирает mGBA этой
кнопкой, исходный профиль подготовки при этом не меняется. Проверка missing
ROM/NRO выполняется при запуске; отдельные индикаторы наличия в списке пока
не добавлены. Ни ручной импорт, ни forwarder на HOME этим этапом не реализованы.

Перед запуском фоновой проверкой заново читается библиотека, сверяется receipt,
проверяется безопасный обычный файл с GBA-заголовком и канонический mGBA NRO.
Только затем на UI-потоке вызывается `envSetNextLoad` с двумя заключёнными в
кавычки путями и обычное завершение Borealis. Ошибка планирования не закрывает
