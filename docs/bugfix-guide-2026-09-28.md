## Рабочий процесс для каждого фикса

1. Воспроизвести по сценарию из карточки.
2. Снять лог: QR-отчёт из Help или `/switch/pipensx/pipensx.log`;
   грепать по тегам (`[torrent]`, `[install]`, `[diagnostic]`, …), не читать целиком.
3. Фикс → `make -f Makefile.pc test` обязательно; для Switch-кода ещё `make switch`,
   для CLI — `make pc`. Новые строки локалей — через `en-US` + `scripts/check_i18n.py`.
4. Формат QR-логов: `src/app/bug_report.hpp` строго в локстепе с `scripts/decode_report.py`.

### F1. Деградация скорости до стопа (24–27.09, после всех торрент-фиксов) — ✅ ИСПРАВЛЕНО 28.09
- Симптомы: 500–700 КБ/с → 5–10 КБ/с → стоп за час при хорошем интернете (Ра, Dobsik28, Galt).
- Подозреваемые в коде: `src/core/torrent.c:1969-1976` (`rate_freeze` душит запросы),
  `torrent_set_rate_freeze` (`torrent.c:2384`), strikes/cooldown медленного WiFi,
  отлучение μTP от sequential head пока жив TCP, DHT-зависимость magnet-старта.
- Фикс: логировать причину заморозки (`rate_freeze`, choked-таймауты) в `[torrent]`;
  пересмотреть пороги после `000d259`/`47bccfc`; проверить, что install-гейт
  (`package_coordinator.hpp`) не держит freeze вечно.
- Проверка: сид с дросселированием, скорость не падает в ноль за час; `test_manager` зелёный.
- **Что сделано (28.09).** Механика была храповиком EMA: при каждом выходе
  install-гейта из throttle первый секундный сэмпл мерял полупустой pipeline
  (гейт только что переанкорил admission edge) и просаживал `dl_rate_bps` на
  ~30% за цикл, а рост веткой 1.5x требовал `strikes==0` и полного окна —
  за час pipeline съезжал к минимуму и загрузка останавливалась. Плюс
  strikes/cooldown (до 10 с) капали за таймауты, вызванные самим гейтом.
  Исправлено: (1) `sample_peer_rates` — resume-guard 2 с после снятия
  `rate_freeze`, refill-интервалы выбрасываются, EMA держится
  (`torrent.c`, `RATE_FREEZE_RESUME_GUARD_MS`); (2) penalty за expiry
  (`request_expiry_penalty`) не применяется пока гейт режет запросы — блоки
  всё равно возвращаются в пул; (3) видимость в `[torrent]`: в health-строку
  добавлены `frozen=%d cooldown=%d penalized=%d`, менеджер логирует смену
  состояния гейта (`[torrent] install request gate throttled|paused, rate_freeze=…`).
  Гейт проверен на «вечный freeze»: pause/throttle выходят по гистерезису при
  дренировании буфера, head-piece остаётся requestable при нулевом drain
  (`test_request_gate.cpp`), latch невозможен — freeze-флаг переопросивается
  каждый тик. Тесты: `test_rate_freeze_resume_guard_discards_refill_interval`,
  `test_expiry_penalty_skipped_for_gate_freeze`; `make -f Makefile.pc test`
  (включая live `test_manager`) и `make switch` — зелёные. Часовой сид-тест с
  дросселированием — на железе.
